# ATM 现金清分与钞箱交接平台（演示）

网点 → ATM → 钞箱 → 券别的现金清分闭环：装钞计划锁定、钞箱封存与双人签收出库、
清机按券别逐档录入、短款/长款/残钞/封签破损/离线/重复回传差异、双人复核、
金额修正留痕、钞箱连续轨迹、审计查询。

> 纯 Python 标准库实现（sqlite3 + http.server），**零第三方依赖**。
> 账户、卡号、金额均为演示数据。

## 一条命令启动

```bash
python3 app.py
# 打开 http://127.0.0.1:8000 ，登录页选择一名演示员工即可
```

启动时自动完成：SQLite 迁移建表 → 写入演示样例（装钞 / 清机 / 差额处置）→
启动进程内补传队列（每 2s 轮询）→ 启动 Web 服务。

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--port 8080` | 指定端口 |
| `--reset` | 删除旧库后重新初始化并写样例 |
| `--no-seed` | 只迁移，不写样例 |
| `--queue-interval 5` | 补传队列轮询间隔（秒） |

环境变量 `ATM_DB`（数据库路径，默认 `./data/atm.db`）、
`ATM_ATTACH`（附件目录，默认 `./data/attachments`）。

## 业务规则

- **装钞锁定**：计划为「草稿」可改明细；锁定后不可改；装钞要求计划已锁定且钞箱已封存。
- **钞箱封存**：封存后封签号写入，数量不能直接修改；装柜前必须封存。
- **双人签收**：钞箱离开网点必须两名**不同**且均属该网点的员工签收；
  两人同时领取同一钞箱，条件更新 + IMMEDIATE 事务保证只有一人成功。
- **清机录入**：按券别逐档录入实点/残钞张数，自动汇总实点、残钞与差额；
  自动生成 短款 / 长款 / 残钞 / 封签破损 / ATM离线 / 重复回传 六类差异。
- **重复回传**：以回传批次号判重；在线已回传或离线已暂存的批次再次提交一律拦截并留差异。
- **离线补传**：离线时数据落库为补传任务（挂起），恢复在线后进程内队列自动补传。
- **金额修正**：经办人 ≠ 审批人、必须填原因；原值/新值/原因/审批人全部留痕；
  关联短/长款差异金额随之调整。
- **双人复核**：两名不同且同网点员工复核通过前，禁止关闭清机单；驳回需重新复核。
- **网点权限**：所有写操作与页面/附件访问均按员工-网点关系隔离，越权返回 403。

## 页面

ATM 台账（按网点分组卡片）· 装钞计划 · 清机录入（右对齐数字列、差额实时计算）·
钞箱轨迹（封签连续时间线、双人签收节点）· 差额复核（金额与处理期限高亮、逾期脉冲）·
审计查询（动作留痕，按网点/关键字/动作过滤）。
界面配色：银灰底、墨绿主色、金色点缀。

金额修正留痕、网点权限、离线补传队列，共 16 个用例。

## 目录结构

```
app.py       单命令入口（迁移 + 种子 + 队列 + Web）
db.py        SQLite schema / 自动迁移 / 串行化事务
services.py  业务服务层（全部规则与审计）
queue.py     进程内补传任务队列（守护线程）
seed.py      演示样例数据
web.py       HTTP 路由 / 会话 / JSON 动作接口 / 附件
views.py     服务端渲染页面
static/      app.css（银灰/墨绿/金）、app.js
tests/       业务规则测试
data/        运行后生成：atm.db 与 attachments/（已在 .gitignore）
```
